## 遇到的問題

1. 【壞掉】應付帳款頁「送出付款單」按鈕外觀完全可點（未 disabled），點下去卻跳出「會計未獲授權執行『送出付款單』，請洽負責人於『角色與核准』開啟」的 toast，且事後 AP 頁一直顯示「不相符：明細合計 21,000，總帳 2101 是 -0，差 21,000 元」。問題有兩層：(a) 這個按鈕在會計角色底下應該要嘛不顯示、要嘛顯示原因並且不可點（畫面規範「看得到就要按得動」），現在是先讓人點了才報錯；(b) 更嚴重的是，一旦被擋，系統沒有提供給會計角色任何「記錄這筆付款」的正規替代路徑，逼得我必須用「建立傳票」手動繞過 AP 模組，直接造成 AP 子帳與總帳長期不一致（除非之後有人用送出付款單把這張帳單結掉，但那樣銀行又會被重複扣一次 21,000）。這是資料完整性風險，不只是體驗問題。

2. 【難用】「建立傳票」（財務頁 header）與「新增應收單」「新增應付帳單」抽屜開啟時沒有任何 loading 動畫或轉場提示，從點擊到內容完整可互動要 2–3 秒。前 4 次嘗試點「建立傳票」時，我在點擊後 1 秒內截圖看到空白頁面，誤判為按鈕完全沒反應（幾乎要記成壞掉），後來刻意等 3 秒才發現其實有開，只是渲染很慢又沒有任何視覺回饋（沒有 spinner、沒有骨架屏）。建議至少加一個立即出現的 loading 骨架或 spinner。

3. 【難用】新增應收單畫面：「應收總額（含稅）」「未稅金額」「代收營業稅」三個欄位有自動連動計算（改總額會自動算出未稅與稅額），但如果依序點擊三個欄位分別輸入，游標移到下一個欄位時舊的自動計算值還留著、新輸入的文字是「插入」而不是「取代」，導致我第一次操作打出「150000150005」這種亂碼金額。要嘛欄位取得焦點時自動全選、要嘛在三個欄位之間做真正的雙向同步（避免使用者以為要逐欄手動填寫）。

4. 【難用】應付帳單新增畫面裡「借方科目」下拉選單，用滑鼠點開後在清單裡點選項目沒有生效（下拉關閉但欄位仍顯示「請選擇」），必須改用程式化的 select 賦值才成功；換算成使用者操作等於「點了看起來選中了，其實沒選中」。這與帳號管理頁「看起來能按、其實什麼都沒發生」是同一類問題，建議檢查這個下拉元件的點擊事件綁定。

5. 【難用】收款登記（登記收款）與建立傳票兩個抽屜的「日期」欄位是完全不同的元件：前者是自訂的分段輸入（yyyy/月/dd 三段），用 triple-click 或整段貼上會把值打散成亂碼（例如打「2026-08-20」變成「6082/00/20」），必須先點年份段、逐段分別打「2026」「08」「20」才會正確；後者是原生 `<input type="date">`，可以直接一次性設定整個日期字串。兩種元件混用、行為不一致，一般使用者若照著在後者上學到的操作方式去填前者的日期，很容易打錯而不自知（因為欄位不會報錯，只會安靜地顯示錯誤的日期，需要使用者自己盯著看才發現）。

6. 【建議】新增應收單／應付帳單時系統只有「到期日」欄位，沒有「開立日期／交易發生日」欄位，所以傳票一律使用當日（今天，08-30）作為交易日期，即使我在摘要裡寫明「8/5 銷貨給宏達實業」，帳上實際的傳票日期仍是 08-30 而不是 08-05。這會讓月底才補記八月初單據時，所有傳票日期都擠在月底那一天，對報表按日期區間篩選、或核對「入帳當天是否即時」會有影響。建議在應收/應付單新增畫面加一個獨立的「單據日期」欄位，不要與「到期日」共用同一顆時間鍵，也不要預設吃系統當日。

## UI 易懂度評分：3/5

理由：核心的三張憑證式畫面（應收帳款／應付帳款／傳票總帳）文案清楚、有自動勾稽提示（例如「本頁合計等於總帳 X 的餘額」「不相符：...」），這點對沒受過訓練的會計非常友善，出錯時系統會主動告訴我哪裡對不上。扣分主要來自三點：(1) 角色權限邊界只在點擊當下用 toast 告知，沒有事先在畫面上標示「這顆按鈕你按不動」，逼我實際點錯才知道，且錯了以後系統不提供替代的正規路徑；(2) 抽屜開啟動畫慢且無任何載入提示，讓我一度誤判功能故障；(3) 兩種日期輸入元件混用、行為不一致，容易打錯值卻沒有任何錯誤提示。這些都是「看起來很像壞掉、其實是設計沒配套」的情況，對第一次上手的使用者殺傷力不小。
