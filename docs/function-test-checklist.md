# 功能測試清單

驗的是**算出來的數字對不對**，不是介面通不通。`scripts/function-test.ts` 自己
砍掉重建一個拋棄式資料庫、自己啟動一個 `laysi-server` 連上去、跑完一遍真實的
帳務流程再逐項對帳，跑完把伺服器收掉。**不會碰到工作用的資料庫。**

```bash
bun scripts/function-test.ts
TEST_DB=laysi_function_test TEST_PORT=8091 bun scripts/function-test.ts   # 可覆寫
```

操作走 REST（畫面通道）。MCP 是同一個註冊表的另一個介面，等價性由
`registry parity` 與 `scripts/mcp-role-matrix.ts` 顧著，算術只在這裡驗一次。

日期一律用 **+08:00 的當日**。拿 UTC 日期當帳務日，會把今天開的傳票記到明天，
然後每一張報表都在傳票之前結帳——那不是報表壞了，是測試自己記錯日子。

## 其他兩層

- `cargo test --workspace`：240 個單元測試。另有 9 個需要資料庫的案例，
  用 `TEST_DATABASE_URL=... cargo test --workspace -- --ignored` 跑。
  **改過欄位或 SQL 之後 `--workspace` 可能沿用舊的測試二進位**（時鐘偏移會讓
  cargo 誤判 Fresh），單獨跑該 crate 會通過而 workspace 仍紅——先
  `cargo clean -p <crate>` 再跑。
- `bun scripts/markdown-test.ts`：公告與規章內文的 Markdown 子集。走的是
  `Markdown.tsx` 產生的 React 元素樹，不需要瀏覽器，也順帶釘住兩件事——原始 HTML
  一律當成文字，`javascript:` 不會變成連結。
- MCP 介面：見 [mcp-test-checklist.md](mcp-test-checklist.md)。
