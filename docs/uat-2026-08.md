# UAT 檢查清單 · 2026-08-30

一次全流程驗收：六個角色在瀏覽器上把一家公司從空的資料庫帶到月結完成，
過程中不看原始碼、不打 API、只用畫面。本檔是結論，八個場次的原始逐步紀錄
在 `uat-2026-08/`，測試帳號的密碼已在收錄時移除。

角色與帳號：系統管理員、負責人（王大山）、會計（陳美玲）、人資（林雅婷）、
員工（張志豪、李佳蓉）。走過的路徑：網頁初始化 → 首次設定精靈 → 建帳號 →
建人事資料 → 抓政府行事曆 → 發公告與規章 → 打卡／請假／加班／請款 →
人資簽核 → 計薪過帳 → 進銷貨與收付款 → 固定資產 → 報支簽核 → 預算 →
簽核門檻 → 帳務差異修正。

## 待修

  付款單那一項修好之後這一類少掉大半。

## 不是缺陷

這幾項在測試中被回報過，查證後不成立，重複出現時不必再開單。

- **四個「按鈕看起來能按、按了沒反應」** ── 測試機 Chrome 的 Bitwarden
  外掛注入 `bit-notification-bar-root`（closed shadow root），蓋在頁面
  右側把合成滑鼠點擊吃掉。`document.elementFromPoint()` 在按鈕正中央回傳
  的是那個外掛的元素；把它 `display:none` 之後同一個座標立刻點得動。
  鍵盤 Enter 一路都有效，因為它不經過命中測試。
- **「送出付款單完全沒反應」** ── 實際上回的是 `not_permitted`，toast 在
  截圖前就消失了。真正的問題是上面「已修」的付款單那一項。
- **公告內文的錯字** ── 那是測試時打進去的內容，不是系統文案。
- **休假申請頁尾的「依據」寫死特休** ── 它解釋的是頁首那張特休餘額卡，
  標成特休是對的；真要改是把它移到卡片旁邊。

## 給下一次的建議

瀏覽器層的自動化不值得進 CI：這一輪五個「壞掉」的回報有三個是自動化假象
（覆蓋層吃點擊、toast 提前消失），而抽屜動畫與原生 `select` 的彈出清單
本來就不受合成事件控制。值得沉澱的是**劇本本身**，寫進 `function-test.ts`：
進銷貨 → 收付款 → 計薪 → 簽核 → 三張表三邊平衡，那裡已經有 `must` 與
`expectEq` 的骨架。上面第一項就是這樣被抓出來的——測試早就存在，缺的只是
一家設定填完整的公司。
