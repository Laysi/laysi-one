# UAT 檢查清單 · 2026-08-30

一次全流程驗收：六個角色在瀏覽器上把一家公司從空的資料庫帶到月結完成，
過程中不看原始碼、不打 API、只用畫面。本檔是結論，八個場次的原始逐步紀錄
在 `uat-2026-08/`，測試帳號的密碼已在收錄時移除。

角色與帳號：系統管理員、負責人（王大山）、會計（陳美玲）、人資（林雅婷）、
員工（張志豪、李佳蓉）。走過的路徑：網頁初始化 → 首次設定精靈 → 建帳號 →
建人事資料 → 抓政府行事曆 → 發公告與規章 → 打卡／請假／加班／請款 →
人資簽核 → 計薪過帳 → 進銷貨與收付款 → 固定資產 → 報支簽核 → 預算 →
簽核門檻 → 帳務差異修正。

## 待修

- [ ] **應付帳款的「送出付款單」不看權限就畫出來**（`screens/Payables.tsx`）
  ── 全檔沒有讀 `permissions`，會計按下去才被 `execute_payment` 擋。職責
  分離本身是對的（會計建帳單、出納付款），問題是畫面沒說，而且被擋之後
  會計沒有任何合法路徑記這筆付款，只能手開傳票，於是應付子帳與總帳從此
  差一個付款金額而畫面上修不掉。實測要負責人查總帳、作廢那張手開傳票、
  重送付款單，跨兩個角色四個步驟才修得回來。
  修法照既有模式：`list_payables` 回 `can_pay`／`pay_blocked_reason`，
  畫面在 `false` 那列不畫按鈕改印原因，與 `list_expense_claims` 的
  `can_approve` 一致。
- [ ] **應收單沒有「開立日期」欄位** ── `create_ar_invoice` 後端收
  `issued_on`，但 `screens/Receivables.tsx` 只送 `due_on`，所以補記月初
  的單據，傳票日期會記成當天。
- [ ] **應付帳單連參數都沒有** ── `create_ap_bill` 沒有 `issued_on`，
  MCP 也補不了。月底補記整月單據時，傳票日期全擠在同一天。
- [ ] **休假申請的錯誤訊息指錯地方**（`screens/LeaveRequest.tsx`）── 起訖日
  預設 `businessToday()`，落在週末時時數為 0，畫面印「所選時段落在上班
  時間之外，請改選 09:00 至 18:00 之間的區間」，但時間欄填的正是那段。
  錯的是日期不是時間，而且使用者還沒動任何欄位就先看到紅字。週末與假日
  開這一頁必定重現。
- [ ] **權限錯誤只用會自動消失的 toast 呈現** ── 使用者離開畫面幾秒再回來
  就不知道剛才發生過什麼。凡是「按了才知道不能按」的地方都有這個問題，
  上面第一項修好之後這一類就會少掉大半。

## 體驗改善

- [ ] **抽屜開啟 2–3 秒沒有任何載入提示** ── 兩位使用者各自誤判成按鈕壞掉。
  加骨架屏或 spinner。
- [ ] **金額三欄連動時不全選** ── 含稅／未稅／稅額互相計算，游標移到下一欄
  時舊值還在，新輸入是插入不是取代，實測打出 `150000150005`。欄位取得
  焦點時全選即可。
- [ ] **沒有「人資」角色** ── 人資相關權限只掛在負責人與會計身上，人資只能
  設成會計，連帶拿到全套財務權限，而逐人薪資明細仍看不到。
- [ ] **待處理清單漏項** ── 人資總覽不算待簽核的加班與補登申請，財務總覽
  不算待簽核的報支。
- [ ] **MCP Token 沒有複製鈕**（`screens/MyMcp.tsx`）── 同一頁的連線位址有，
  首次設定精靈的臨時密碼也有，最重要的那個字串反而要自己選取。
- [ ] **補登打卡要先核准上班卡** ── 先按下班會跳拒絕訊息，畫面沒有事先說。
- [ ] **公司資料沒有地址與電話欄位** ── 精靈與基礎設定都沒有，存不進系統。
- [ ] **文件上傳不能自訂名稱** ── 只吃檔名。
- [ ] **「會計」與「會計師」在下拉選單裡分不出來** ── 要點開權限對照表才知道
  哪個是一般內部會計。
- [ ] **精靈完成頁是空的** ── 沒有總結剛才設定了什麼，交接要逐頁自己核對。

## 不是缺陷

這幾項在測試中被回報過，查證後不成立，重複出現時不必再開單。

- **四個「按鈕看起來能按、按了沒反應」** ── 測試機 Chrome 的 Bitwarden
  外掛注入 `bit-notification-bar-root`（closed shadow root），蓋在頁面
  右側把合成滑鼠點擊吃掉。`document.elementFromPoint()` 在按鈕正中央回傳
  的是那個外掛的元素；把它 `display:none` 之後同一個座標立刻點得動。
  鍵盤 Enter 一路都有效，因為它不經過命中測試。
- **「送出付款單完全沒反應」** ── 實際上回的是 `not_permitted`，toast 在
  截圖前就消失了。真正的問題是上面「待修」的第一項。
- **公告內文的錯字** ── 那是測試時打進去的內容，不是系統文案。
- **休假申請頁尾的「依據」寫死特休** ── 它解釋的是頁首那張特休餘額卡，
  標成特休是對的；真要改是把它移到卡片旁邊。

## 給下一次的建議

瀏覽器層的自動化不值得進 CI：這一輪五個「壞掉」的回報有三個是自動化假象
（覆蓋層吃點擊、toast 提前消失），而抽屜動畫與原生 `select` 的彈出清單
本來就不受合成事件控制。值得沉澱的是**劇本本身**，寫進 `function-test.ts`：
進銷貨 → 收付款 → 計薪 → 簽核 → 三張表三邊平衡，那裡已經有 `must` 與
`expectEq` 的骨架。上面第一項就是這樣被抓出來的——測試早就存在，缺的只是
一家設定填完整的公司。
